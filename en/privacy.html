Privacy and terms

Updated 8 November 2026 · Applies to the allowlist beta

  • Keys are temporary by default and never enter logs, drafts or run records. After signing in, use natural-language Settings or Lean Model connection to save an encrypted key to your account, replace it or delete it. Only the last four characters are shown.
  • You sign in to the workbench (app.theoremos.top) using an approved email address, with a code or a password you have set. Problems, conversations and runs are isolated by account. The admin panel provides no route to another account’s content; operators retain server maintenance access.
  • The platform is free during the research preview. Model calls are billed by the provider you choose, to your API key.
  • This site uses no cookies and no advertising trackers. GitHub access requests and feedback are public.

Privacy

This site

The website and proof archive are static pages hosted on Cloudflare; their source files are public on GitHub. This site sets no cookies and loads no advertising or cross-site tracking scripts. Cloudflare processes access logs under its privacy policy.

Access requests and feedback

Access requests and feedback sent through GitHub are public issues that anyone can read. Do not include API keys, email addresses or other personal information. Email sent to liuzhenhao@westlake.edu.cn is used only to answer your request and coordinate early access. It is not published or shared.

Online workbench

The online workbench is at app.theoremos.top. This section summarizes its data handling. The workbench’s privacy notice and terms carry the current version.

Account and sign-in

  • The allowlist beta currently admits approved email addresses only. Sign in with an email code or a password set after signing in, and accept the current terms before using the service.
  • The server stores email, account ID, creation time, terms consent version and time, and a password hash if you enable a password. Email is used for login, research notifications and terms notices, not marketing. Alibaba Cloud DirectMail processes recipient addresses and message content.
  • Your account also records two times: when you first submitted a run and when a run first passed acceptance. During the preview we use these times to see whether onboarding works, mostly as totals and conversion rates. We do not record your clicks or page views. Both go when you delete your account.
  • Before a code is sent you type a picture captcha. The workbench server draws it; no third-party bot check is used.
  • After you sign in, the server sets a session cookie that is sent only over HTTPS and cannot be read by scripts. It keeps you signed in, belongs to the workbench only and is not used for tracking.

What admins can see

  • The admin page shows allowlist sources, account details, status, first-use times and current allowance usage to manage access and capacity.
  • The admin page neither shows nor offers any way to read an account's statements, sources, proofs, run records or API keys. When maintainers look at run records on the server is described under Retention and deletion.

Research-end emails

  • When a run ends on its own (finished or failed), the workbench emails your sign-in address with the run title, the outcome, the time taken and a link back to the run. The email contains no statement, source, proof or API key. Runs you stop yourself send nothing.
  • This is on by default. Turn off "Email me when research ends" in the account menu to stop it.

Network and hosting

The workbench server is reached through a Cloudflare Tunnel: every request goes over HTTPS to Cloudflare first and is then forwarded to our server. Cloudflare handles this traffic under its privacy policy. To limit code requests, the server counts requests per visitor IP in memory and never writes these counts to disk.

API keys

  • Your API key is submitted over HTTPS and passed to the isolated container for that run through a private input channel. It does not appear in container arguments or service logs.
  • Agent commands do not receive keys in their environment. Task completion cleans up the isolated container and execution credentials. The current page may retain the key you entered in memory for the same conversation; refreshing clears it.
  • If the key appears in model output or an error message, it is replaced with [REDACTED] before anything is saved.
  • Keys access only your selected model provider, including model-list checks you request. They are temporary by default. After signing in, natural-language Settings and Lean Model connection let you save or replace an AES-256-GCM encrypted key bound to your account and provider. Only the last four characters are shown; the server decrypts the key to make calls.
  • Without opting to save, no key enters persistent data. Remove saved keys in natural-language Settings or Lean Model connection; deleting an account removes its live key records. Maintenance backup retention is described below.

Research records

The server stores the statement, task description and model settings you submit, along with the candidate sources, Lean checks, events and usage produced during the run. These records let you review runs and download archives in the workbench.

Sharing

A share link lets anyone holding it read the Lean problem, proof, acceptance result, model, environment, duration and usage, plus the natural-language problem, confirmation method, back-translation and formalization correspondences when available. It excludes keys, email, provider addresses, logs and Agent conversations. Revoking the link disables it.

Model providers

Runs and follow-up questions send relevant problems, source, conversations and Lean feedback to your selected model provider. Processing and retention follow that provider’s privacy policy. Select the provider and its key before sending.

Browser storage

Task drafts, a recovery copy of a replaced draft and panel widths are kept in session storage for the current tab and are cleared when you close it. Local storage holds only your interface language, your appearance choice (light or dark), the desktop notification setting, the run you last viewed (so the workbench reopens where you left off) and module plans you save to the local plan library. None of it contains your API key, and you can clear it in your browser settings.

Feedback from the workbench

"Report a problem" in the workbench opens the feedback page on this site with "Web workbench", your browser, system, window size and interface language filled in, plus the error type after a failed run. It adds no run ID, email address, statement or API key. Opening the page sends nothing; the report is published on GitHub only after you confirm it, and you can edit or remove these details first.

Retention and deletion

  • Each account keeps up to 20 run records. You can delete finished runs in the workbench at any time.
  • A sign-in expires after 30 days without use. You then sign in again, and your records are kept.
  • Deleting an account immediately removes its live email, password, keys, runs, shares, archives, knowledge and module plans, and cancels its running tasks. To prevent allowance resets through account recreation, only a usage identifier, current-window counts and expiry remain, without email, account ID or content. They expire at the original window end, within 24 hours by default.
  • Operators may access server records for maintenance, backups, troubleshooting or abuse handling, without selling or publishing your content. Private maintenance backups are kept for at most 7 days and removed by operators, for recovery only. Live deletion does not rewrite them immediately. Recovery first uses an isolated directory; completed deletion requests must be checked again before reopening service.
  • Upgrades during the research preview may require clearing data. We will announce this on this site in advance. Download the sources and archives you want to keep.

Terms of use

Research preview

TheoremOS is a research preview provided as is. The service may be interrupted, rate limited or changed. There is no uptime guarantee and no guarantee that a proof will be found.

Costs

The beta platform is free; your provider bills your API account for model calls. Defaults are 10 minutes / 400,000 tokens for formalization, then 5 minutes / 200,000 tokens for proof, adjustable before sending. Work stops on reported usage and requests in progress may exceed the cap; token budgets are not monetary caps. Calls already made are billed even if a task fails, is cancelled or times out.

Your content

The statements and sources you submit, and the proofs produced in your runs, remain yours. They appear in the public archive only if you choose to publish them. Submit only content you have the right to use, and do not submit secrets, personal data or confidential material.

Acceptable use

Do not try to break run isolation, attack the service or other users, or upload malicious code, and do not use the run environment for computation unrelated to mathematical research. Sessions that break these rules may be terminated.

Verification results

Independent Lean acceptance verifies the frozen Lean statement’s proof. Correspondence with the natural-language meaning is reviewed by models or confirmed by you and shown separately; Lean does not verify translation fidelity. Check the original meaning, source and receipts before relying on a result in a paper or competition.

Changes

This page may be updated as the service opens. Significant changes will be dated here and noted on the home page.
